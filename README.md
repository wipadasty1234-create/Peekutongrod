# ตัวตัง ก๋วยเตี๋ยวไก่บุฟเฟต์ — ระบบหลังร้าน (PWA)

แอปเดียว ไม่มี backend, ข้อมูลทั้งหมดเก็บในเครื่อง (IndexedDB) ผ่านมือถือ/คอมทั่วไป

## วิธีใช้งาน (แนะนำ — ให้ใช้งานได้เต็มรูปแบบ เช่น ติดตั้งเป็นแอปหน้าจอโฮม + ใช้งานออฟไลน์)

Service worker (ที่ทำให้ใช้งานออฟไลน์ได้และติดตั้งเป็นแอปได้) ต้องรันผ่าน http/https ไม่ใช่เปิดไฟล์ตรงๆ (file://) ทางเลือกที่ง่ายที่สุด:

**ตัวเลือก 1: Netlify Drop (ง่ายสุด ไม่ต้องสมัครก็ได้)**
1. ไปที่ https://app.netlify.com/drop
2. ลากทั้งโฟลเดอร์นี้ไปวาง
3. จะได้ลิงก์เว็บที่เปิดผ่านมือถือได้ทันที กด "เพิ่มลงหน้าจอโฮม" จากเบราว์เซอร์เพื่อใช้เหมือนแอป

**ตัวเลือก 2: GitHub Pages**
อัปโหลดโฟลเดอร์นี้เป็น repo แล้วเปิดใช้ GitHub Pages ในหน้า Settings

**ตัวเลือก 3: รันในเครื่อง (สำหรับทดสอบ)**
ถ้ามี Python ติดตั้งอยู่ ให้เปิด terminal ในโฟลเดอร์นี้แล้วรัน:
```
python3 -m http.server 8080
```
แล้วเปิด http://localhost:8080 ในเบราว์เซอร์

> หมายเหตุ: ถ้าเปิดไฟล์ index.html ตรงๆ (ดับเบิลคลิก) แอปจะยังใช้งานได้ปกติ (บันทึกข้อมูล/คำนวณ) แต่จะไม่สามารถติดตั้งเป็นแอปหรือใช้งานออฟไลน์แบบเต็มรูปแบบได้

## ข้อมูลสำคัญ — สำรองข้อมูลเป็นประจำ

ข้อมูลทั้งหมดอยู่ใน IndexedDB ของเบราว์เซอร์บนเครื่อง/มือถือเครื่องนั้นเท่านั้น **ถ้าลบแอป ล้างข้อมูลเบราว์เซอร์ หรือเปลี่ยนเครื่อง ข้อมูลจะหายไปทันที**

- กด **"Export ข้อมูล"** ที่หน้าแรกเป็นประจำ (แนะนำทุกสัปดาห์) จะได้ไฟล์ .json เก็บไว้ (เช่น Google Drive/LINE เก็บไฟล์)
- ย้ายเครื่องใหม่: เปิดแอปเครื่องใหม่ แล้วกด **"Import ข้อมูล"** เลือกไฟล์ backup ล่าสุด ระบบจะดึงข้อมูลกลับมาใช้ต่อได้ทันที

## โครงสร้างข้อมูล (สำหรับพัฒนาต่อ)

- `menuItems` — คลังเมนู (ชื่อ, ราคา, หมวด, สถานะเปิด/ปิดขาย)
- `dailySales` — ยอดขายรายวัน 1 record/วัน (รายการ, รายรับตามระบบ, รายรับจริง)
- `rawMaterials` — วัตถุดิบ (คงเหลือปัจจุบัน, ต้นทุนเฉลี่ยถ่วงน้ำหนัก, รอบนับ daily/weekly)
- `stockReceiving` — ประวัติการรับเข้าวัตถุดิบแต่ละครั้ง
- `stockCounts` — ประวัติการนับสต๊อกคงเหลือแต่ละครั้ง
- `consumptionLog` — ปริมาณ/ต้นทุนที่ใช้ไปจริง (คำนวณอัตโนมัติตอนนับสต๊อก) = ต้นทุนวัตถุดิบ (COGS)
- `expenses` — รายจ่าย (วัตถุดิบ/ดำเนินงาน) พร้อมรูปสลิป

## แนวทางพัฒนาต่อ (เฟส 2)

- เพิ่ม sync หลายเครื่อง (เช่น Firebase/Supabase) โดยใช้โครงสร้างตารางเดิม
- เพิ่มระบบผู้ใช้/สิทธิ์ ถ้ามีพนักงานหลายคนกรอกข้อมูล
- แจ้งเตือนอัตโนมัติให้ Export ข้อมูลทุกสัปดาห์
